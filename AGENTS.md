# Descent

Elegant now playing display for Last.fm, showing song metadata, album art and
local weather. Runs as an Express server that renders pug templates and serves
hand-written browser JavaScript compiled by gulp.

Deployed at [descent.live](https://descent.live) on Google App Engine, behind
Cloudflare.

## Project Structure

| Path | What it is |
|---|---|
| `server.js` | The server. Express routes plus every upstream API call. ES modules (`"type": "module"`). |
| `lib/*.js` | Server logic pulled out of `server.js` so it can be tested without credentials or network, like the Last.fm proxy and Spotify match ranking. |
| `source/js/*.js` | Per-page entry modules, one per view (`now`, `landing`, `config`, `hue`). |
| `source/js/utility/*.js` | Shared browser modules, imported by the entries. See Code Conventions. |
| `source/scss/` | Styles, one file per page plus shared partials. |
| `views/` | Pug templates. `template/layout.pug` is the shell, `template/external.pug` holds CDN library mixins. |
| `public/` | Build output. `public/javascripts` and `public/stylesheets` are gitignored and regenerated by gulp. |
| `test/*.test.js` | Unit tests on Node's built-in runner, covering `lib/` and the pure browser modules like `utility/color.js` and `utility/cookies.js`. |
| `test/browser/` | Playwright smoke tests and the fake upstream APIs they run the server against. |

The browser never talks to Last.fm, Spotify, Hue, or the weather provider
directly. Those all proxy through `server.js` so the keys stay server side.
Last.fm used to be the exception, with its key handed to the page, which is how
it got copied into other projects and rate limited (#203). The now playing
page doesn't poll on a timer. It asks `/app/lastfm/recent?wait=1` with the
ETag of what it already shows, and `lib/lastfm.js` holds that request until
the answer changes or 50 seconds pass. While anyone is waiting on a user, one
server loop polls Last.fm for them and answers every waiting page at once.
Upstream calls share one budget, the loop slows down evenly when more people
are watched than it covers, and it backs off further if Last.fm rate limits.
When the track changes, the server also looks up its Spotify art and the
user's play counts once and sends them in the same answer as `details`, so the
page makes no lookups of its own. `lib/spotify.js` caches art per track.
Held requests count toward App Engine's concurrency limit, which is why
`app.yaml` raises `max_concurrent_requests`.

## Environment

| Variable | Used for | Required |
|---|---|---|
| `LASTFM_API_KEY` | Server side Last.fm calls | yes |
| `LASTFM_POLL_INTERVAL` | Fastest the server polls Last.fm for each watched user, in milliseconds, default 3000. It stretches under load. | no |
| `OPENWEATHERMAP_KEY` | Weather | no, weather degrades |
| `SPOTIFY_CLIENT` / `SPOTIFY_SECRET` | Album and artist art | no, art degrades |
| `HUE_CLIENT` / `HUE_SECRET` | Hue OAuth and remote API | no, lights degrade |
| `DESCENT_PORT` | Local port, default 3000. App Engine sets `PORT`. | no |

Every one of these is wired in `.github/workflows/deploy-app-engine.yaml` from
repo variables and secrets. Adding a new one means adding it there too or it
silently won't exist in production.

## Development

```
yarn                 # install
yarn gulp build      # compile scss and js into public/
yarn dev             # build, then watch with browsersync on :3333 and nodemon
yarn start           # run the server on the last build
yarn test            # build, lint, then unit tests, the same thing CI runs
yarn smoke           # browser smoke tests on the last build, see below
```

`yarn test` is the gate. It fails on a Sass error, any lint error, or a failing
test. There's no global gulp to install, since the scripts use the local one.

Tests use `node:test` and `node:assert`, with no framework. Anything worth
testing should be pure enough to import without a DOM, a server, or
credentials. Pass dependencies like a search function in, or split the logic
into its own module, the way `lib/spotify.js` and `utility/color.js` are.

`yarn smoke` runs `test/browser/*.spec.js` in Playwright against the real
server, started with `test/browser/upstreams.js` preloaded. That file replaces
`fetch` for Last.fm, Spotify and OpenWeatherMap with canned answers, and opens
a control port the tests use to change what's playing. It needs a build first
and Chromium installed once with `yarn playwright install chromium`. CI runs it
as its own `smoke` job, and deploys wait for it as well as `build`.

Don't add a `build` or `gcp-build` script to `package.json`. App Engine runs
either one during deploy, and CI has already built `public/`. An empty
`gcp-build`, which Google suggests for turning this off, breaks the deploy
under Yarn 1 with "Script must exist". That's why building on its own is
`yarn gulp build`.

## Code Conventions

Style is enforced by `eslint.config.mjs`: two-space indent, single quotes,
semicolons, unix line endings, no `var`. Run `npx eslint .` before pushing.

**Browser files are native ES modules, with no bundler.** Each view loads one
entry with `<script type="module">`, and the browser follows its imports. Import
siblings by relative path with the `.js` extension, like
`import { getCookie } from './cookies.js'`. There is no jQuery or js-cookie:
use the DOM directly, `utility/request.js` for JSON requests, `utility/cookies.js`
for cookies, and `toggleDisplay` in `utility/general.js` for the fades. Color
Thief and chroma.js still load from the CDN as classic scripts, so the files
that call them declare them in a `/* global */` header.

Server-rendered values like the username reach the browser as `data-`
attributes, never as inline script. Inline `onclick` handlers can't reach module
functions, so links that act like keys carry `data-key` instead.

Kiosk browsers lag behind, so the client sticks to what shipped around 2020:
optional chaining and `??` are fine, but avoid things like `AbortSignal.timeout`
and top-level `await`.

Other observed conventions, followed for consistency rather than because
anything enforces them:

- `let` over `const`, even for values that never get reassigned
- Quoted keys in fetch option objects: `{ 'method': 'post', 'headers': headers }`
- Comments explain why a thing is done, not what the line does
- Prose in comments, commit messages and PR bodies uses en dashes, not em dashes

## Pull Requests

Branch names are short and topical: `hue-auth`, `spotify-album`, `eslint-flat-config`.

PR bodies are conversational prose. No headers, no bullet summaries of the
diff, no emoji section markers. Explain what was wrong, what changed and why,
in the voice of someone describing it to a colleague. Include measurements when
a change is supposed to improve something.

Titles are imperative and sentence case: `Remove Dark Sky weather support`.

## Release Strategy

The version in `package.json` drives releases. Bump it **only** when a PR
contains release-worthy changes:

| Release-worthy | Not release-worthy |
|---|---|
| Source changes (`server.js`, `source/`, `views/`) | CI and workflow changes |
| Runtime dependency changes | Dev-only dependency changes |
| Security fixes | Docs-only changes |
| | Tooling and repo config |
| | Agent docs |

Semver:

- **Patch** — bug fixes, dependency updates, security fixes
- **Minor** — new features, non-breaking additions
- **Major** — breaking changes to config cookies, stored state, or self-hosting setup

Bumping on every PR is what caused repeated `package.json` conflicts between
open PRs, since every branch touches the same line. Not bumping for tooling and
docs is what lets more than one PR be open at a time.

## Deployment

`deploy-app-engine.yaml` builds on every push and pull request, but the deploy
job is gated to `refs/heads/main`. A merge to `main` ships to production
immediately; there is no staging.

Cloudflare sits in front. The rendered HTML is never cached, but static assets
are cached for 24 hours, so they're served under
`/app/static/<package.json version>/` and a version bump misses the cache on
its own. The version is in the path rather than a query string so that module
imports, which resolve relative to the importing file, inherit it. That means a release needs no manual
purge, but it also means a source change shipped *without* a version bump will
keep serving the cached asset until the day is up.

App Engine only accepts requests from Cloudflare. Its firewall allows
Cloudflare's published IP ranges and denies everything else, so the
`appspot.com` address returns 403 and nothing can skip the Cloudflare layer.
Turning off Cloudflare's proxy for the domain would take the site down, and if
Cloudflare ever adds ranges (listed at cloudflare.com/ips), they need adding as
App Engine firewall rules.

Deploys authenticate to GCP with GitHub's OIDC token. The provider only accepts
tokens from this repo's `main` branch, which is the only place the deploy job
runs.

Every response carries a Content-Security-Policy with a fresh nonce. Cloudflare
reads that nonce to tag the bot detection script it injects into pages, so
keep the nonce if the policy changes, and add any new script, style or font
host to it.

Open now playing pages check the server's version every minute and reload
themselves, at a random point within 30 seconds, when a deploy changes it.

## Gotchas

- `public/javascripts` and `public/stylesheets` are gitignored, so a stale local
  build never reaches production. CI always rebuilds from source.
- The landing page picks a random Last.fm user from a hardcoded list in
  `server.js`. Those are real accounts and some are useful for testing, for
  example `ben-xo` has loved tracks where the default user has none.
- Weather needs the visitor to grant geolocation, so it will look broken in a
  headless or permission-denied context.
