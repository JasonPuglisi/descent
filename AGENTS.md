# Descent

Elegant now playing display for Last.fm, showing song metadata, album art and
local weather. Runs as an Express server that renders pug templates and serves
hand-written browser JavaScript compiled by gulp.

Deployed at [descent.live](https://descent.live) on Google App Engine, behind
Cloudflare.

## Project Structure

| Path | What it is |
|---|---|
| `server.js` | The entire server. Express routes plus every upstream API call. ES modules (`"type": "module"`). |
| `source/js/*.js` | Per-page entry scripts, one per view (`now`, `landing`, `config`, `hue`). |
| `source/js/utility/*.js` | Shared browser code. Not modules, see Code Conventions. |
| `source/scss/` | Styles, one file per page plus shared partials. |
| `views/` | Pug templates. `template/layout.pug` is the shell, `template/external.pug` holds CDN library mixins. |
| `public/` | Build output. `public/javascripts` and `public/stylesheets` are gitignored and regenerated by gulp. |
| `scripts/build_and_test.sh` | What `npm test` runs: gulp build, then eslint. |

The browser never talks to Spotify, Hue, or the weather provider directly.
Those all proxy through `server.js` so the keys stay server side. Last.fm is
the exception: the browser calls it directly, and the key is injected into the
page at render time rather than committed (#203).

## Environment

| Variable | Used for | Required |
|---|---|---|
| `LASTFM_API_KEY` | Injected into the page, browser calls Last.fm with it | yes |
| `LASTFM_POLL_INTERVAL` | Milliseconds between Last.fm polls, default 10000 | no |
| `OPENWEATHERMAP_KEY` | Weather | no, weather degrades |
| `SPOTIFY_CLIENT` / `SPOTIFY_SECRET` | Album and artist art | no, art degrades |
| `HUE_CLIENT` / `HUE_SECRET` / `HUE_ID` | Hue OAuth and remote API | no, lights degrade |
| `DESCENT_PORT` | Local port, default 3000. App Engine sets `PORT`. | no |

Every one of these is wired in `.github/workflows/deploy-app-engine.yaml` from
repo variables and secrets. Adding a new one means adding it there too or it
silently won't exist in production.

## Development

```
yarn                 # install
gulp build           # compile scss and js into public/
gulp                 # build, then watch with browsersync on :3333 and nodemon
npm test             # gulp build + eslint, the same thing CI runs
```

`npm test` is the gate. It fails the build on any lint error.

## Code Conventions

Style is enforced by `eslint.config.mjs`: two-space indent, single quotes,
semicolons, unix line endings, no `var`. Run `npx eslint .` before pushing.

**Browser files are plain scripts, not modules.** They are loaded as separate
`<script>` tags and share globals, which is why each one starts with a
`/* global ... */` header listing what it uses from its siblings. Referencing a
new function across files means updating that header or lint fails with
`no-undef`. This has caught real bugs, including several implicit globals that
were leaking onto `window` (#215).

Other observed conventions, followed for consistency rather than because
anything enforces them:

- `let` over `const`, even for values that never get reassigned
- Quoted keys in fetch option objects: `{ 'method': 'post', 'headers': headers }`
- Comments explain why a thing is done, not what the line does
- Prose in comments, commit messages and PR bodies uses en dashes, not em dashes

## Pull Requests

Branch names are short and topical: `hue-auth`, `spotify-album`, `eslint-flat-config`.

PR bodies are conversational prose. No headers, no bullet summaries of the
diff, no emoji section markers. Explain what was wrong, what changed and why,
in the voice of someone describing it to a colleague. Include measurements when
a change is supposed to improve something.

Titles are imperative and sentence case: `Remove Dark Sky weather support`.

## Release Strategy

The version in `package.json` drives releases. Bump it **only** when a PR
contains release-worthy changes:

| Release-worthy | Not release-worthy |
|---|---|
| Source changes (`server.js`, `source/`, `views/`) | CI and workflow changes |
| Runtime dependency changes | Dev-only dependency changes |
| Security fixes | Docs-only changes |
| | Tooling and repo config |
| | Agent docs |

Semver:

- **Patch** — bug fixes, dependency updates, security fixes
- **Minor** — new features, non-breaking additions
- **Major** — breaking changes to config cookies, stored state, or self-hosting setup

Bumping on every PR is what caused repeated `package.json` conflicts between
open PRs, since every branch touches the same line. Not bumping for tooling and
docs is what lets more than one PR be open at a time.

## Deployment

`deploy-app-engine.yaml` builds on every push and pull request, but the deploy
job is gated to `refs/heads/main`. A merge to `main` ships to production
immediately; there is no staging.

Cloudflare sits in front. The rendered HTML is never cached, but static assets
are cached for 24 hours at unversioned URLs, so a deploy serves fresh HTML
against stale JavaScript until the cache is purged (#220).

## Gotchas

- `public/javascripts` and `public/stylesheets` are gitignored, so a stale local
  build never reaches production. CI always rebuilds from source.
- The landing page picks a random Last.fm user from a hardcoded list in
  `server.js`. Those are real accounts and some are useful for testing, for
  example `ben-xo` has loved tracks where the default user has none.
- Weather needs the visitor to grant geolocation, so it will look broken in a
  headless or permission-denied context.
